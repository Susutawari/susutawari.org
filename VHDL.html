  • ISEのプロジェクトディレクトリを変更（別のPCに移行など）したときに、iMPACTがbitファイルを見つけられなくなる。
    原因：iMPACTの起動設定ファイル(*.ipf)にパスが保存されるので、これが異なると見つけられない。
    対策：該当の*.ipfを削除する。
  • XSTのディフォルト・オプションを変更しておかないと、FFがIOBにパックされずに、合成毎にタイミングがずれることがある。
    ISE(7.1.04i)のプロセス・ツリー内で、"Synthesize XST"を右クリックして、"Properties" -> "Xilinx Specific Options" -> "Pack I/O Registers into IOBs"を「AUTO」->「YES」に変更しておく。この設定を変更しておかないと（AUTOのままだと）、 
    entity XXX is
 Port ( A : in std_logic;
        B : out std_logic);

architecture Behavioral of XXX is

 signal BUF : std_logic;

begin

 process (CLK)
 begin
  if rising_edge (CLK) then
   BUF <= A;
   B <= BUF;
  end if;
 end process;

end Behavioral;
    で、"BUF"を観測しようとして、ロジアナ（オシロ）を当てる為の外部観測ピン"TestPort"を追加するため、 
    entity XXX is
 Port ( A : in std_logic;
        B : out std_logic;
        TestPort : out std_logic);

architecture Behavioral of XXX is

 signal BUF : std_logic;
 signal TestPort : std_logic;

begin

 process (CLK)
 begin
  if rising_edge (CLK) then
   BUF <= A;
   B <= BUF;
   TestPort <= BUF;
  end if;
 end process;

end Behavioral;
    などとすると、配置状況（ピンアサインの位置や他の回路ブロックとの関係など）によってはFFがIOB内ではなく、LUTのものが使われてしまい、結果として"BUF"に観測ピンをアサインしたときと、しないときで遅延が変わってしまうことがあり、危険。観測ピンならまだ可観測だが、内部ロジックで分岐している場合にはディバッグ困難？！つまり、さっきまで動いていたところが、ロジック上無関係な回路をいじることで（タイミングがおかしくなり）動かなくなる可能性がある。

  • ISE のエディタを Meadow (Multilingual enhancement to gnu Emacs with ADvantages Over Windows) にするための設定
    1. Meadow をインストール
    2. Meadow で左側に行番号を表示するために、wb-line-number
      → 移転先（推測）: https://github.com/aktiger/wb-line-number 作者のサイトは無し。同じ .el v1.5.5 の第三者による写し をインストール（Meadowをインストールしたディレクトリ以下の"lispディレクトリ"に、ダウンロードした"wb-line-number.el"をコピーする）
    3. 環境変数に HOME = .emacsを置くディレクトリ・パス を追加
    4. .emacs を .emacs を参考に修正
      （Windowsの標準環境で".emacs"のように"."で始まり、拡張子のないファイルを作るには、Meadowで保存し直すことで作成可能。）
    5. ISE(7.1.04i)の"Edit" -> "Preferences" -> "ISE General" -> "Editors"で、 Text editor の Editor を Custom にして、Command line syntax に 「Meadowのインストールパス\RunMW32.exe $1」を指定。
    6. ISE 8.1i以降は「{C:\usr\local\share\meadow\bin\RunMW32.exe} +$2 $1」などと、パスを含めたプログラム名を"{}"で括る必要がある。
    以上により、ISEのソースツリーにあるHDLファイルなどをダブルクリックしたときに、Meadowが起動するようになる。
    参考：Meadow(emacs)のキー操作一覧1, 一覧2, 一覧3.
  • One-Shot Pulse (微分パルス) の生成方法 
    process (CLK)
begin
 if rising_edge (CLK) then
  B <= A;
 end if;
end process;

C <= A and not B;
    で、入力Aに対するOne-Shot Pulse出力Cが得られる。
    process (CLK)
begin
 if rising_edge (CLK) then
  B <= A and not B;
 end if;
end process;
    では入力Aをイネーブル入力とする、トグルFFになってしまう。

  • CORE Generatorで作ったコアをISEのプロジェクト中に追加する方法

  • process文中の動作2

 if rising_edge (CLK) then
  B <= A;
  C <= B;
 end if;
end process;
    とした場合、A -> B -> C となるD-FFが2個生成される。

  • process文中の動作1
    process文中がシーケンシャルというのは、センシティビティ信号の信号遷移単位でのシーケンスではなく、センシティビティ信号遷移直後の信号伝達が文の上からシーケンシャルという意味。わかりにくいな・・うーんと、文の上から順に実行されるんだけど、センシティビティ信号の変化毎に各行が逐次実行されるわけではないということ。

    例： 
    process (CLK)
begin
 if rising_edge (CLK) then

   A <= '0';

   if B='1' then
    A <= '1';
   end if;

 end if;
end process;
    はBによりAの値が変化するが、
    process (CLK)
begin
 if rising_edge (CLK) then

   if B='1' then
    A <= '1';
   end if;

   A <= '0';

 end if;
end process;
    では、AはBによらず常に'0'となる。
    これは、 
    process (CLK)
begin
 if rising_edge (CLK) then

   A <= '0';

 end if;
end process;
    若しくは、単に A <= '0'; と等価。

    process (CLK)
begin
 if rising-edge (CLK) then
  B <= A;
  D <= C;
  E <= D;
 end if;
end process;
    としたとき、始めの"CLK"の遷移でB <= A;が実行され、次の"CLK"遷移でD <= C;が実行されるわけではない。B <= A; D <= C; E <= D;は全て1回の"CLK"遷移で同時実行される。
